## 一、页面系统

### 页面类型注册表（M2 核心）

每个页面类型注册时声明 `multi_instance` 属性：

| 类型               | 单/多实例 | 默认出现在"新建"菜单 | 说明                 |
| ------------------ | --------- | -------------------- | -------------------- |
| markdown           | 多        | ✅                    | 通用 Markdown 页     |
| todo               | 多        | ✅                    | 待办清单             |
| calendar           | 多        | ✅                    | 日程                 |
| workout            | 多        | ✅                    | 健身计划             |
| music              | 多        | ✅                    | 音乐/歌单            |
| game               | 多        | ✅                    | 游戏库               |
| review             | 多        | ✅                    | 观后感               |
| timeline           | 多        | ✅                    | 时间线               |
| gallery            | 多        | ✅                    | 图片画廊             |
| **bookshelf**      | **单**    | ❌                    | 阅读书架，全局唯一   |
| **idea_box**       | **单**    | ❌                    | IDEA 栏，全局唯一    |
| **vault**          | **单**    | ❌                    | 密码保险箱，全局唯一 |
| **future_plan**    | **单**    | ❌                    | 未来规划，全局唯一   |
| **daily_greeting** | **单**    | ❌                    | 每日问候，全局唯一   |
| **habit_tracker**  | **单**    | ❌                    | 习惯追踪，全局唯一   |

**单实例类型的添加方式**：不在"新建"菜单里出现。用户在设置页手动启用。

**加新页面类型的方式**：加一个 Vue 组件文件 + 在注册表注册一行。不改核心代码。

## 四、设计原则（约束所有功能）

1. **本地优先**：数据永远在本地，云同步是可选增强
2. **页面类型可插拔**：加新类型不改核心代码
3. **单实例 vs 多实例**：注册时声明，由注册表统一管理
4. **数据与配置分离**：数据存 SQLite，配置存 JSON
5. **前后端解耦**：前端负责 UI，后端负责数据
6. **可替换资源**：开屏动画、主题、字体等，用户可导入
7. **开放格式**：数据可导出为 Markdown / JSON / 标准格式
8. **不锁定**：任何时候可迁移到其他工具
