## 一、页面系统

### 页面类型注册表

每个页面类型注册时声明 `multi_instance` 属性：

| 类型          | 单/多实例 | 默认出现在"新建"菜单 | 说明               | 状态    |
| ------------- | --------- | -------------------- | ------------------ | ------- |
| markdown      | 多        | ✅                    | 通用 Markdown 页   | ✅ M2    |
| todo          | 多        | ✅                    | 待办清单           | ✅ M2    |
| gallery       | 多        | ✅                    | 图片画廊           | ✅ M2    |
| collection    | 多        | ✅                    | 链接收藏           | ✅ M2    |
| **bookshelf** | **单**    | ✅（M4 起）           | 阅读书架，全局唯一 | ✅ M4    |
| idea_box      | 单        | ❌                    | IDEA 栏            | 待定 M6 |
| vault         | 单        | ❌                    | 密码保险箱         | 待定    |
| future_plan   | 单        | ❌                    | 未来规划           | 待定    |
| habit_tracker | 单        | ❌                    | 习惯追踪           | 待定    |

**单实例类型的添加方式**：
- 后端在创建时强制校验：已存在同类项 → 409
- 前端不显示已存在的单实例类型选项

**加新页面类型的方式**：只改 `backend/app/page_types.py`。

## 八、设计原则（约束所有功能）

1. **本地优先**：数据永远在本地，云同步是可选增强
2. **页面类型可插拔**：加新类型不改核心代码
3. **单实例 vs 多实例**：注册时声明，后端强制校验
4. **数据与配置分离**：数据存 SQLite，配置存 JSON
5. **前后端解耦**：前端负责 UI，后端负责数据
6. **可替换资源**：开屏动画、主题、字体等，用户可导入
7. **开放格式**：数据可导出为 Markdown / JSON / 标准格式
8. **不锁定**：任何时候可迁移到其他工具
