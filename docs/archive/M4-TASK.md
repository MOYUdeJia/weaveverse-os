## 1. 目标

给 Weaveverse OS 加**阅读书架**模块。用户能导入书籍（EPUB / TXT / PDF）、看封面、记录进度、打开阅读器阅读。

**M4 只做这一件事。** 不加搜索、不加标注、不加统计、不碰 M2/M3 已有系统。

---

## 2. 范围

### 必须做

- 新增数据表存储书籍元信息和进度
- 后端 API：上传、列表、详情、更新、删除、封面、内容
- 文件存到 `backend/data/books/{id}/`
- EPUB 提取元数据 + 封面 + 章节；TXT 直接读；PDF 只提元数据（不内嵌阅读）
- 前端书架页：最近阅读 + 全部书籍 + 排序筛选 + 导入按钮
- 前端阅读器：EPUB / TXT 内嵌，PDF 走系统应用打开
- 阅读进度自动保存
- `bookshelf` 页面类型（M2 已注册为单实例）走专属渲染，不走 blocks 系统

### 不要做

- 不做全文搜索、标注、高亮、笔记、阅读统计
- 不做云同步
- 不改 `nav_items`、`blocks`、页面模板系统
- 不引入 UI 组件库、TypeScript
- 不引入 epub.js / foliate-js / pdf.js（太重）
- 不支持 MOBI / AZW3 / KF8
- PDF 不内嵌阅读

---

## 3. 技术选型（你自己定）

- **数据表字段**：你自己根据需求设计
- **接口 URL 和返回结构**：你自己定，保持 RESTful
- **前端组件拆分**：你自己组织
- **EPUB 解析**：可以用 `ebooklib`，也可以用标准库 `zipfile` + `xml` 手写。你自己判断哪个更合适，说明理由
- **PDF 元数据**：可以用 `pypdf`
- **封面**：EPUB 内置封面直接保存；PDF / TXT 用占位图

---

## 4. 关键约定（必须遵守）

- **加新功能不改老代码**：bookshelf 专属渲染集中在 `WorkspacePanel.vue` 一处判断
- **文件存储规范**：`backend/data/books/{book_id}/original.{ext}` 和 `cover.{ext}`
- **`.gitignore`**：`backend/data/books/` 里的文件不进 git，但要留 `.gitkeep`
- **XSS 消毒**：EPUB 章节 HTML 渲染前必须 DOMPurify 消毒（同 M2）
- **阅读器形式**：全屏浮层，不新开窗口
- **进度保存**：切换章节或滚动时调 API 更新，节流保存

---

## 5. 验收标准

### 5.1 接口验收

上传一本 EPUB / TXT / PDF，都能成功返回元数据。列表、详情、删除、封面、内容接口能正常调用。

### 5.2 GUI 验收

- [ ] 侧边栏新建一个 `bookshelf` 类型项，右侧显示书架
- [ ] 导入 EPUB → 显示封面 + 书名 + 作者
- [ ] 导入 TXT / PDF → 显示占位封面
- [ ] 点书籍 → 打开阅读器
- [ ] EPUB：能切章节，能看到正文
- [ ] TXT：能滚动阅读
- [ ] PDF：有"用系统应用打开"按钮
- [ ] 切换章节或滚动 → 关闭阅读器后书架进度条更新
- [ ] 重启应用 → 进度保留
- [ ] 删除书 → 卡片消失，`backend/data/books/{id}/` 目录也删
- [ ] **桌面窗口里点"导入书籍"→ 文件选择器正常弹出**（M2/M3 没验证过，必测）
- [ ] M2/M3 的页面、区块、模板都正常
