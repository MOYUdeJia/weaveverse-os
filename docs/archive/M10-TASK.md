## 第一部分：修复项

### 1.1 首次启动弹窗（带“不再提示”）

**现状**：每次打开软件都显示“Weaveverse OS 怎么用”的提示。

**要求**：
- **只有第一次启动时**弹出使用说明
- 弹窗内有一个复选框：**“不再提示”**
- 勾选后，下次启动不再弹出
- 设置里保留一个“再次显示使用说明”的入口
- 状态存到 `appearance.json` 或独立的 `onboarding.json`

### 1.2 右侧工作区图片残留

**现象**：每次进入软件后，右侧工作区上方有一小片图片残留，一直存在。疑似每次登录欢迎界面的图片底部没被完全清除。

**排查方向**：
- 欢迎封面（splash）的 DOM 元素是否在动画结束后完全移除
- 是否有残留的 `background-image` 或 `position: fixed` 的装饰层
- z-index 是否正确

**要求**：找到根因，彻底清除残留。

### 1.3 背景不透明度可设置

**现状**：当前背景是半透明的（M7 实现的“背景图 + 半透明 UI”）。

**要求**：
- 设置 → 外观 中加一个“背景不透明度”滑块（0% – 100%）
- 100% = 完全不透明（背景图完全遮住底层）
- 0% = 完全透明（只有 UI 底色）
- 默认值保持当前效果（如 85%）
- 实时预览

## 第二部分：主题与欢迎封面系统

### 2.1 主题入口

**现状**：主题切换目前藏在“外观”设置里，用户不容易找到。

**要求**：
- 在设置中单独增加一个“主题”页（或“外观 → 主题”标签）
- 显示当前主题名称
- 预设主题列表（保持现有 5 套）
- **支持导入主题文件**（`.wvtheme` 或 `.json`）
- 支持导出当前主题

**主题文件格式**（你定义，给出规范）：
- 包含：CSS 变量集合 + 名称 + 作者 + 版本
- 示例结构写进文档

### 2.2 欢迎封面替换

**目标**：让用户可以替换软件启动时的欢迎封面（开屏动画）。

**要求**：
- 设置 → 外观 → 欢迎封面 中：
  - 显示当前封面（预览）
  - “替换封面”按钮 → 选择文件
  - 支持格式：图片（PNG/JPG/GIF）+ 视频（WebM/MP4）+ Lottie JSON
  - 替换后立即生效（下次启动）
- 封面文件存到 `backend/data/splash/`
- 默认封面保持不变

### 2.3 第三方开机动画格式支持

**背景**：用户参考了 `dragon-codex-boot`（Windows 启动动画启动器，播放 1080p 视频后交接给客户端）和 `dsh-chat-wallpaper`（动态壁纸，支持视频和 Web 壁纸）。

**要求**：
- 我们的开屏动画支持以下格式：
  - **视频**：WebM（推荐，体积小）、MP4
  - **Lottie JSON**（`.json` / `.lottie`）
  - **图片**：PNG / JPG / GIF（静态或简单动画）
- 设置里可切换格式类型
- 视频自动循环（如果用户提供的是短循环视频）
- 播放时长：默认 2 秒，可配置（3 / 5 / 10 秒）
- 播放结束后淡出进入主界面

**技术方案**：
- 视频用 `<video>` 标签（`autoplay` `muted` `playsinline`）
- Lottie 用 `lottie-web`（M0 已提到，如果未安装则安装）
- 图片直接显示

**参考**：
- `dragon-codex-boot` 使用独立启动器播放视频后交接，我们不需要独立启动器，直接在应用内播放。
- `dsh-chat-wallpaper` 使用 Wallpaper Engine 资源，我们只支持通用视频/图片。

## 第三部分：打包为独立 APP + 桌宠系统

### 3.1 打包为独立 APP

**目标**：用户双击 `.exe` 就能启动整个应用，不需要手动跑 `python main.py`。

**技术方案**（你选一个，说明理由）：
| 方案                        | 说明                                | 优点                    | 缺点                     |
| --------------------------- | ----------------------------------- | ----------------------- | ------------------------ |
| **PyInstaller**             | 把 Python + 前端打包成一个 `.exe`   | 简单，Windows 友好      | 体积大（~150MB），启动慢 |
| **Nuitka**                  | 编译成机器码                        | 体积小，启动快          | 编译时间长，兼容性需验证 |
| **Tauri + Python sidecar**  | Tauri 做壳，Python 后端作为 sidecar | 体积小（~10MB），启动快 | 需要 Rust 环境，配置复杂 |
| **PyWebview + PyInstaller** | 保持当前架构，用 PyInstaller 打包   | 与现有代码无缝          | 体积大                   |

**推荐**：先做 **PyInstaller 打包**（快速可用），后续再考虑 Tauri 迁移。

**打包要求**：
- 生成单文件 `.exe`（或文件夹，你判断）
- 包含前端 `dist/` + 后端代码 + 依赖
- 数据库和用户数据放在用户数据目录（`%APPDATA%/WeaveverseOS/`），不是 exe 旁边
- 提供 `build.py` 或 `build.ps1` 脚本
- 双击 exe 后，无控制台窗口（或可选显示）

### 3.2 桌宠系统规划（只规划，不实现）

**目标**：在应用窗口上显示一个可拖动的桌宠，与音乐悬浮球联动。

**规划内容**（写进 `docs/FEATURES.md` 的“未来规划”或新建 `docs/PET-SYSTEM.md`）：

**核心需求**：
- 桌宠可拖动（鼠标按住拖动，松手吸附到窗口边缘）
- 桌宠与音乐悬浮球联动：
  - 播放音乐时，桌宠跟着节拍跳动
  - 点击桌宠可播放/暂停
- 桌宠支持多种形象（用户上传 GIF / 序列帧 / Live2D）
- 桌宠有简单动画（待机、播放、暂停）

**技术选型**（只规划，不实现）：
- 渲染：HTML + CSS 动画 / Canvas / Live2D
- 拖动：pointer events + requestAnimationFrame
- 节拍：复用音乐悬浮球的 Web Audio API AnalyserNode
- 形象格式：GIF（简单）、序列帧（PNG 序列）、Live2D（复杂，需要 SDK）

**排期**：M11+（本任务书只写规划，不实现）

### 3.3 RVC 音色（记录，不实现）

**背景**：RVC（Retrieval-based Voice Conversion）是开源的实时变声框架，可以训练自己的音色模型。

**可行性**：
- RVC 需要 GPU 推理，模型文件较大（~100MB+）
- 实时变声需要音频流处理（麦克风输入 → RVC → 输出）
- 集成复杂度高

**决定**：**M10 不实现**，记录到 `FEATURES.md` 的“未来规划”，排期 M12+。
